retry classifier

Scale-hardening — resilient structured-output calls (A1)

1b627a1
Restored on complete_structured the timeout + retry/backoff the C-5 migration dropped vs complete_json. Test-first — 7 new tests, suite 342 → 349 green, offline smoke-gate 6/6.
Shipped

A transient 429 or hung call no longer silently loses tasks

scale · A1 · the C-5 regression

Wrapped the Instructor→LiteLLM call in a per-call timeout and a bounded retry/backoff loop, reusing the existing llm_client retry helpers import-only (no router/credential paths touched).

Beforecomplete_structured called the provider with no timeout, retry, or rate-limit backoff — the legacy complete_json path had all four. BetterStructured output regains the production resilience the regex path had — the prerequisite for parallelizing the per-node loop (B1), where concurrency would otherwise multiply transient-failure task-loss.

scale · C1

BeforeEvery node's coverage check flagged its whole section INCOMPLETE inline, pre-dedup — a single confident miss per section drove the real run to ~100% INCOMPLETE, and merged-away duplicates still counted.
AfterA pure CoverageGate (reusing the shared ConfidenceGate) flags the FINAL deduped set report-level: a task is INCOMPLETE only when one of its source_refs belongs to a section whose report is confident (checker_confidence ≥ floor) AND has genuine misses. No inline path → no double-flag.

BetterThe INCOMPLETE rate reflects survivors and real misses, not a blanket sweep — and the INV-4 flagbomb control still goes RED through the new gate, proving it's wired.

Embedding-tier corpus filter drops cross-section duplicate "misses"

C-4 · STEP 3.5

The piece that actually drops the real-run rate: filter each reported miss against the final deduped corpus by similarity before the gate sees it.

BeforeThe structural move flags correctly, but most "misses" on a real SOW are cross-section duplicates — work already captured as a task extracted elsewhere — and the checker, seeing only one section, still reports them. They'd flag genuine tasks INCOMPLETE.
AfterA feature-stage CoverageCorpusFilter (reusing the dedup MiniLM embedder) tiers every miss vs the final corpus: drop ≥0.85 (already covered), advisory 0.70–0.85, genuine <0.70. Only genuine misses survive to the gate; a section with none no longer flags.

BetterCross-section duplicates stop poisoning the signal — the mechanism behind the ~100%→<40% drop. Env-gated (SOW_COVERAGE_CORPUS_FILTER, default OFF so the INV-4 gate stays byte-deterministic; on in prod). 13 deterministic tests; adversarially reviewed (11 agents) → 0 defects.

The pipeline refuses to push known-bad work to Jira

STEP 3.5 · PushGate

A pure, read-only gate that decides which approved tasks may actually be created in Jira.

BeforeNothing stopped an INCOMPLETE / low-confidence / ambiguous task — or any task from a DEGRADED run — from being pushed; and a re-push could duplicate work already created in Jira.

run()'s eight phases are extracted into reusable stage methods; a new PipelineRunner sequences them from a StageRegistry, selectable behind a flag and proven byte-equivalent to run() offline.
