Harness Engineering · System Study · June 2026

The model was never the problem. The harness was missing.

SOW-to-Jira is an AI pipeline with almost no engineering shell around the AI. This study separates the core AI system — the model, prompts, and decisions — from the harness that's supposed to make it reliable, then re-audits and re-architects the whole system along that seam.

“100% incomplete, zero merges, a critic flagging at zero confidence — none of these are model failures. They're holes where a harness should be.”

Subject  6 cognition agents · ~5,900 LOC Method  12-agent harness-lens workflow Verdict  Strong AI, near-absent harness
01 — The two halves

Core AI vs. harness — and the seam between them.

Harness engineering is building the deterministic shell around the AI so that turning a 103-page SOW into 509 Jira tickets is measurable, repeatable, and controllable — no matter which model or prompt is wired in. The agents are the AI: a model, a prompt, one decision. Everything else is the harness: enforcing the output contract, verifying what came back, gating low-confidence verdicts, tracking health and cost, keeping state durable, and recovering from failure deterministically. The split must be clean enough that you can swap models or rewrite a prompt without touching the engineering.
Non-deterministic · evolves freely

The Core AI

  • Six cognition agents — each a model + prompt + one scoped decision (what tasks live here, is this actionable, are these duplicates, what's missing…)
  • The prompt templates the model consumes
  • The choice of model/provider per decision — free to swap GPT → Claude → local
The Contract
Deterministic · engineered for stability

The Harness

  • Structured-output enforcement at the model boundary (Instructor over LiteLLM)
  • Computational verification — schema, truncation, "work-was-done" checks
  • Confidence gates before any verdict mutates a task
  • Typed StageResult + a pipeline state machine, durable & resumable
  • Per-run injected credentials, health report, and cost meter; an action gate on the Jira push

Between them sits scaffolding — the versioned, independently-tested boundary contract: a Pydantic response model + model policy per agent. It's where the non-deterministic model meets the deterministic harness.

03 — The findings, as harness gaps

Every headline bug is a missing piece of harness.

Problem in plain language, the harness principle it violates, and the fix.

CriticalBoundary

The output contract is fictional

The system has typed shapes the AI is meant to fill, but never asks it to — it requests free text, scrapes it, checks the scrap against the shape, and quietly drops whatever doesn't fit. A malformed answer looks identical to no answer.

PrincipleStructured output is the contract, not a parse step.

Fix

Hand the Pydantic response model to the call via Instructor; the only thing crossing the seam is a valid object or a typed FAILED. Add the three missing response models.

CriticalBoundary

A hard 4096 cap silently truncates big answers

Every AI call is capped at the same small output size regardless of the job. On the big run the duplicate-finder's answer was cut off mid-sentence, became unreadable, and the system reported "zero duplicates" instead of "truncated."

PrincipleSize the token budget to the payload; never hard-code it.

Fix

Remove the fixed 4096; size the budget per call; treat a length cut-off as a first-class failure that retries bigger or returns DEGRADED. Batch dedup pairs so each call fits.

CriticalHarness

Failures are swallowed and look like success

When any AI step breaks, the code hands back what it got and carries on — so a broken run and a perfect run are indistinguishable. The first real run looked clean while its dedup step was quietly dead.

PrincipleFailure is data, never a swallowed exception.

Fix

Each stage returns a typed StageResult (OK / DEGRADED / FAILED + reason). Ban the "except → return inputs" pattern; one exception boundary in the stage runner.

CriticalHarness

No confidence gate → 100% flagged INCOMPLETE

If the coverage checker suspects anything is missing — even a low-confidence hunch — it marks every task in that section incomplete. Run across all sections before duplicates are removed, that flagged 100% of tickets.

PrincipleNo model verdict mutates a task below its confidence gate.

Fix

Gate INCOMPLETE on the checker's own confidence clearing a floor, applied once post-dedup at the batch level — not per-section, verbatim, in the loop.

CriticalHarness

Critic flags fire at zero confidence

The reviewer agent slaps warning labels on tasks even when it openly says it has zero confidence in its own judgment. A model that's effectively shrugging still gets to mark every ticket problematic.

PrincipleInferential verifiers must themselves be confidence-gated.

Fix

A single confidence floor across both the fix and flag paths. A conf=0.00 critique produces no flag and no mutation.

HighHarness

No "work-was-done" check

The dedup step found many near-identical pairs, got an unusable cut-off answer, and concluded "no duplicates" — the worst possible reading. Nothing flagged that it achieved nothing on an obviously non-trivial workload.

PrincipleVerify both ways — did this stage actually do work?

Fix

A deterministic assertion: dedup over N candidates yielding 0 merges marks the stage DEGRADED, tied to the truncation check.

HighBoundary

No action guard on the Jira push

Nothing stops a half-baked or flagged ticket from being pushed into the real Jira project. The riskiest, hardest-to-undo step has the weakest safety check — flags become labels, never blocks.

PrincipleTool/action guardrails before an irreversible side effect.

Fix

A PushGate blocks tasks carrying INCOMPLETE / LOW_CONFIDENCE flags, or any task from a DEGRADED/FAILED run, without an explicit reviewer override.

CriticalHarness

The pipeline can't tell if a step worked

All steps run in one long straight-line function that never asks "did that work?" A broken step and a good step look identical to the code after them, so a half-broken run finishes reporting success.

PrinciplePer-stage health as a typed result; failure is data.

Fix

A Stage protocol + a StageRunner that owns the one exception boundary, timing, verify, gate, and persist — and a pipeline state machine that gates on each predecessor's status.

HighHarness

Quality checks run in the wrong order

The verify steps run too early — judging tasks before duplicates are removed, then immediately mutating them on opinions that were never confidence-checked. The ordering itself manufactures noise.

PrinciplePlan → execute → verify; only gated verdicts mutate state.

Fix

Node loop plans/extracts only; dedup executes; critic + coverage run as a single post-dedup, gated batch over the final task set.

HighHarness

No resumability — a crash loses everything

If the server restarts partway through a long run, all work so far is thrown away and the user re-processes the whole PDF, including the expensive indexing and extraction.

PrincipleStages are deterministic and resumable, not an open loop.

Fix

Persist each stage result as it completes; on restart resume from the first incomplete stage.

CriticalHarness

Credentials & model are process-global

One set of credentials and one selected model for the whole process. Two concurrent runs — or a mid-run settings change — can push to the wrong Jira or call the wrong model with the wrong key. A real leak risk and the biggest multi-user blocker.

PrincipleEnvironment is injected per run, not read from globals.

Fix

Resolve a validated provider config once at a composition root and inject it into the run, the LLM client, and the Jira client. Stop writing creds into the environment.

HighHarness

The measurement half is absent

The code counts tokens and durations then throws them away (the meter was never connected); telemetry ships off by default; there's no dollar cost anywhere; and the quality grader in the repo never grades a run.

PrincipleCost and health are first-class run outputs.

Fix

Connect a real meter; split local health from remote sync; add a cost meter; roll it into a per-run health report; wire a golden-set eval into CI with quality bands.

04 — The elevated architecture

A harness-engineered SOW-to-Jira.

Four moves that build the missing shell — and make the three headline bugs structurally impossible rather than merely fixed.

A · The Seam

AgentSpec (scaffolding) + AgentRunner (harness)

Split the fused agent into two named artifacts with one typed contract between them. The cognition side becomes a frozen, versioned AgentSpec; the harness side becomes a single AgentRunner every model call must cross. Cross this seam and 100%-INCOMPLETE, the silent dedup no-op, and conf=0.00 flagging all become impossible — while swapping a model or prompt is an AgentSpec edit the harness never notices.

  • AgentSpec[I,O] holds all cognition: prompt, builder, response_model (the contract), model policy, gate thresholds — lifted into pipeline/specs/ with fixture tests, no I/O.
  • AgentRunner.run is the one path: build prompt → call in structured-output mode → size tokens → reject truncation → reprompt on schema error → gate → record cost/health → return StageResult.
  • Existing response models get promoted from after-the-fact parse targets to what the model is forced to emit.
  • The six agent classes shrink to one-liners; only OK/gated output may mutate tasks.
StageResult[O]: status: Literal['OK','DEGRADED','FAILED']; output: O | None; reason: str; agent: str; spec_version: str; tokens_in: int; tokens_out: int; cost_usd: float; finish_reason: str
B · The Control Plane

A typed Plan-Execute-Verify pipeline runner

Replace the 270-line linear run() with a Stage protocol, a StageRunner that owns the one exception boundary, and a pipeline state machine. The stage order encodes the PEV "sandwich" and runs verify post-dedup — which alone fixes two of the three headline bugs and makes degraded runs visibly distinct from clean ones.

  • The StageRunner — not the agent — owns timing, the single try/except, the work-was-done check, persistence, and the predecessor gate.
  • Stages: PLAN (classify, extract) → EXECUTE (state, dedup) → VERIFY (coverage, critic, gap-recovery) → PERSIST.
  • Run status = the worst stage status; a FAILED predecessor SKIPS dependents (recorded, not silent).
  • Each stage result is persisted, enabling resume-from so a crash at node 80 of 103 is recoverable.
class Stage(Protocol): name: str; requires: list[str]; def execute(ctx) -> StageOutput; def verify(out, ctx) -> tuple[StageStatus, str]
C · The Guardrail Band

A deterministic verification & gating layer

A thin, fully-tested band every agent output crosses after the schema check and before any mutation — the only code allowed to decide whether a verdict is trustworthy enough to act on. Floors are config, not code, and are unit-tested with no model in the loop.

  • verify.py — computational, always-on, no LLM: assert_work_done (0 merges on >N items → DEGRADED), assert_finish_complete, assert_nonempty_when_expected.
  • CriticGate.admit_flags returns nothing below the floor — kills conf=0.00 flagging.
  • CoverageGate.apply is run-wide, post-dedup, report-level, gated on confidence — the structural fix for 100% INCOMPLETE.
  • PushGate.assert_pushable blocks the Jira push for flagged or degraded-run tasks without override.
ConfidenceGate: field: str; floor: float; on_reject: Literal['drop','flag_low_confidence']; def admit(obj) -> bool
D · The Measurement Harness

Eval, observability & cost

The half that makes the agent observable, gradeable, and affordable — all hanging off the single model-call seam and the typed contracts, so models and prompts can change without touching agent code. It turns the three production failures into red CI and makes a degraded run show a badge instead of a green "Pipeline Complete."

  • Record/replay cassettes at the call seam + an eval harness that replays a frozen 103-node fixture and asserts quality bands in CI (incomplete_rate <= 0.40, merge_count >= 1, zero_conf_flags == 0, no DEGRADED).
  • A per-run health report assembled from per-stage health, persisted and surfaced as a DEGRADED badge in the UI.
  • Tracing behind a port with one Langfuse adapter injected from the composition root, keyed by user & run.
  • A cost meter accumulated into the run report; the node cap gains a max-run-cost companion.
class LLMResult(BaseModel): content: str; finish_reason: str; prompt_tokens: int; completion_tokens: int; usd_cost: float
05 — The structural shifts

Four moves, in priority order.

1

Make the contract real. Hand the response model to the call (Instructor / JSON-mode); delete the regex scrape and the swallow-after-parse. Only a valid object or a typed FAILED crosses the seam.

2

Replace silent-swallow with StageResult. Ban "except → return inputs" across all six agents; one exception boundary in the StageRunner so failure becomes visible run state.

3

Move every confidence gate into the harness. Symmetric across critic fix and flag; coverage INCOMPLETE gated on confidence and applied post-dedup at batch level.

4

Inject environment; make stages durable. Provider config from a composition root instead of globals, per-stage persistence, and a PEV state machine instead of a 270-line linear pass.

06 — Where to start

The minimum viable harness.

The smallest set that makes the engine trustworthy — do this before any of the platform-shaped migration work.

Build these first

  1. Structured output at the seam — the model call takes a response model via Instructor; delete the regex scrape.
  2. Kill the 4096 truncation — size tokens to the payload, treat a length cut-off as a typed failure, batch dedup pairs.
  3. Typed StageResult + ban silent-swallow — every agent returns OK / DEGRADED / FAILED with a reason.
  4. The two confidence gates — CriticGate (no conf=0.00 flags) and CoverageGate (gated, post-dedup, batch).
  5. Work-was-done check — dedup over 100+ candidates merging 0 marks the stage DEGRADED.
  6. Per-run health report — surface OK / DEGRADED / FAILED plus cost, so a degraded run is visibly distinct from a clean one.
