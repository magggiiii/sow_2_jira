Wave 3 — Intelligence-layer quality

1596b0e
Fixed the bugs behind "100% INCOMPLETE / 0 merges / conf=0.00." Each landed test-first; +16 regression tests.
Shipped

Truncated AI responses fail loudly instead of corrupting silently

C-5 · the #1 root cause

Fixed the single setting behind most of the intelligence-layer failures.

BeforeEvery AI call capped at max_tokens=4096; long answers were cut off mid-array, regex-scraped, and the broken result was swallowed as "success" — the cause of 0 dedup merges and ~29/30 extraction failures.
Aftermax_tokens is per-call (default 8192); a length cut-off raises a typed LLMTruncationError instead of returning garbage.

BetterTruncation is now a visible, handleable failure — not invisible data corruption.

Shipped

The critic stops flagging when it has no confidence

H-3

Silenced the noise that flagged every ticket.

BeforeCritic flags were applied regardless of confidence — a conf=0.00 "shrug" still labelled tickets LOW_CONFIDENCE/AMBIGUOUS_SCOPE; it also guessed at duplicates.
AfterAll flag mutations gated at confidence ≥ 0.5; conf=0.00 produces nothing; the duplicate role is removed (dedup owns it).

BetterFlags now mean something — reviewers see real issues, not blanket noise.

Shipped

De-duplication no longer loses data

Dedup merge

Made merges preserve content and order.

Beforekeep_first/keep_second dropped the other task without absorbing its acceptance criteria / deliverables / source refs; a list(set()) lost ordering.
AfterMerges absorb the dropped task's content via _merge_tasks, fix merged_from, and preserve order.

BetterMerging two tickets no longer quietly throws away half their detail.

Shipped

A "did this stage actually do work?" signal

H-2 · H-6

Made a no-op dedup pass visible.

Before0 merges on 100+ candidate tasks looked identical to a clean run — the exact symptom that shipped undetected.
AfterA large input that yields zero merges now records a DEGRADED signal with a reason.

Better"The engine did nothing" is now a detectable state, not silent success.

Shipped

Coverage stops flagging on empty nodes & low confidence

C-4 (slice) · H-7

Began dismantling the 100%-INCOMPLETE flag bomb.

Beforeget_gaps ignored its length filter (firing recovery on empty headings), and any single missed item flagged a whole section INCOMPLETE regardless of the checker's confidence.
Afterget_gaps honors min_text_length; a pure, unit-tested helper gates INCOMPLETE on checker_confidence.

BetterThe signal is being restored. (Full post-dedup, run-wide restructure is gated behind an eval cassette — see "Next.")

Typed result & contract layer

core/results.py

Introduced StageResult (OK / DEGRADED / FAILED / SKIPPED + cost/tokens) and LLMResult.

BeforeStage outcomes were untyped; a failed stage and a successful one were indistinguishable to the code after them.
AfterEvery stage can return a typed status with a reason and cost.

Reusable guardrails + a per-run health report

core/guardrails.py · core/health.py

Turned the ad-hoc gate/verify logic into tested primitives, and gave every run a single health verdict.

BeforeConfidence gates and "did it actually do work?" checks were scattered inline across critic, coverage, dedup and the LLM client; a run carried no overall health — a degraded run looked identical to a clean one.

Wave 5 — Jira robustness

cae9c6a
Make the Jira push production-grade. Mocked-transport TDD, +14 tests (jira_client.py had none).
Shipped

Idempotent, rate-limit-aware, honest Jira push

C-11 · H-11 · H-12

Three real push bugs fixed so a large push survives retries and never lies about success.

BeforeA failed/retried push re-created duplicate issues; a single rate-limit (429) became a permanent half-push; and if an Epic/Story failed, its children were silently scattered as top-level issues while the push still reported success.
AfterTasks remember their jira_issue_key and skip on re-push (no duplicates); 429/5xx are retried with backoff honoring Retry-After; a failed container marks affected children hierarchy_degraded so the UI can surface it.

BetterPushing hundreds of tickets is now safe to retry and honest about partial failures — and the headline feature finally has real tests.

Domain model — normalizing enums

3c13cc8
Closed-set fields hardened against dirty LLM output. +23 test functions (67 cases).
Shipped

Dirty model output coerces instead of silently mis-routing

H-23 · INV-1

Turned three free-text decision fields into typed enums that normalize messy LLM values.

BeforeFields like the dedup decision were plain strings, so a model emitting KEEP_BOTH vs keep_both vs keep both could silently mis-route a comparison — the same class of bug behind dedup oddities.
AfterThey're str-enums with a normalizer that coerces case/whitespace/alias drift to the right member and fails loudly on genuinely-unknown values — every existing string comparison still works unchanged.

BetterThe contract is self-defending: dirty-but-known input is absorbed, unknown input errors visibly instead of slipping through.
