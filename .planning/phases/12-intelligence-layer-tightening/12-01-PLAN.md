<objective>
Wire `json-repair>=0.59` (per D-33 and CONTEXT.md specifics) into both JSON parse paths so malformed long arrays from Gemini Flash don't silently kill extraction or dedup. Add the partial-recovery detector on the extraction agent path so a 22-task section coming back as 14 is flagged `EXTRACTION_PARTIAL`. Critically, wire the consumer end of D-33: extend `CoverageTracker` with `mark_partial(node_id)` and modify `get_gaps()` so partial-recovery nodes flow into gap_recovery (Task 1.3 below). Without that consumer wiring the `EXTRACTION_PARTIAL` audit row is a dead letter — `mark_covered` already fires for any extracted task, so `get_gaps()` cannot see partial-recovery nodes today.

This is foundational for Phase 12: T2 (critic) and T3 (coverage) parallelize with T1, but T5 (extraction prompt tune) and T6 (verification) need the parse fixes in place first. Without this, every other improvement in Phase 12 still drops ~29% of nodes to a JSON delimiter bug.

Purpose: Make `complete_json` and `extract_json` tolerate the markdown-fenced long-array malformation observed in baseline run `20260512-194433-test-sow` (~29 of 30 extraction failures share this root cause). Detect partial recovery so we don't ship "successfully" with half the tasks AND route those nodes to gap_recovery for a second pass.

Output: Two modified parse paths, one extraction-path detector with new return-tuple signature, CoverageTracker partial-state extension, orchestrator wiring, one new pytest file. No new env flag. Default behavior is the new better behavior.
</objective>

    try:

        if _json_repair is not None:

                repaired = _json_repair.loads(cleaned)
                # Recovery succeeded — record it so we can audit how often this path fires.
                if recovery_flag is not None:
                    recovery_flag["recovered"] = True
                with logger.contextualize(agent=agent_name, run_id=self.run_id, node_id=node_id):

                    agent=agent_name,
                    node_id=node_id,
                    action="JSON_REPAIR_RECOVERED",

                            f"Raw (first 500): {raw[:500]}"

                        node_id=node_id,
                    )

                    f"LLM returned unparseable JSON from {agent_name} (stdlib + json-repair both failed). "
