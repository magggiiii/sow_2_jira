# Quick Task 260512-001: First-class OpenRouter provider support

## Goal

OpenRouter is already in `PROVIDER_REGISTRY` and `build_litellm_model` handles the `openrouter/` prefix. Discovery at `/api/providers/openrouter/models` already routes through the OpenAI-compatible path. This task closes the remaining gaps so OpenRouter feels first-class: attribution headers, env example, README guidance, UI helper text, and a smoke script.

## Must-haves

- LLM completions sent via OpenRouter include `HTTP-Referer` and `X-Title` headers
- `.env.example` documents `OPENROUTER_API_KEY` (and the conventional referer/title vars)
- `README.md` has a short "Using OpenRouter" subsection
- UI Settings shows a small helper line under the model select when provider=openrouter, linking to openrouter.ai/models
- A smoke script exists that hits `/api/providers/openrouter/models` and reports model count

## Non-goals

- Curated model list (user uses existing Fetch Models button)
- Combobox/typeahead picker for the 300-model dropdown
- Default model substitution for openrouter

## Tasks

### Task 1 — Attribution headers in `pipeline/llm_client.py`

**Files:** `pipeline/llm_client.py` (around line 269)

**Action:** Extend the `extra_headers` setup so that when `self.provider_config.provider == "openrouter"`, the client adds:
- `HTTP-Referer`: from `OPENROUTER_REFERER` env, default `https://github.com/magggiiii/sow_2_jira`
- `X-Title`: from `OPENROUTER_APP_NAME` env, default `SOW-to-Jira`

Existing Bifrost/Ollama branches are preserved.

**Verify:** Read the file; confirm header dict is populated only when provider is openrouter; no breakage to other branches.

### Task 2 — `.env.example` documentation

**Files:** `.env.example`

**Action:** Add a commented OpenRouter section after the LiteLLM block:

```

OPENROUTER_API_KEY=sk-or-...
# Optional attribution shown on openrouter.ai dashboards/leaderboards
OPENROUTER_REFERER=https://github.com/magggiiii/sow_2_jira
OPENROUTER_APP_NAME=SOW-to-Jira
```

**Verify:** Diff shows additions; no existing keys removed.

### Task 3 — README "Using OpenRouter" subsection

Link to `https://openrouter.ai/models`. Keep it 6–10 lines.

### Task 5 — Smoke script

**Files:** `scripts/verify-openrouter.sh`

**Action:** A short bash script that requires `OPENROUTER_API_KEY` env, POSTs to `http://localhost:8000/api/providers/openrouter/models` with that key, and prints the model count plus first 5 IDs. Documented at top with a usage line.

**Verify:** `bash scripts/verify-openrouter.sh` returns a non-empty model list when the local server is up and a valid key is set.
